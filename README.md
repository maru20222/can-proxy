# can-proxy

Teensy 4.1 で BLITZ R-VIT i-Color FLASH の CAN を車両から切り離し、ECM の代わりに応答する CAN プロキシ／ゲートウェイ。

- 対象車両: 日産 スカイラインクーペ CKV36（パワートレイン CAN 500kbps）
- ボード: Teensy 4.1（PlatformIO）
- CAN トランシーバ: Adafruit CAN Pal（5708 / Digi-Key 1528-5708-ND, TJA1051T/3）× 2
- 切替リレー: Panasonic TQ2-5V（2回路 C 接点・金クラッド接点の信号用）。Teensy が動いていないときは R-VIT を車両に直結する
- 現フェーズ: **ブレッドボード仮実装**。電源は USB、車両から持ってくるのは CAN H/L（＋推奨で信号GND）のみ。R-VIT の電源は車両から直結のまま。

## 1. 全体構成

```
                OBD延長ケーブル（CAN H/L の 6番・14番だけ切断）
 車両 OBD ポート ──────┬──────────── NC ┐
 (6:CAN-H 14:CAN-L)     │                  COM ─────────── R-VIT
                        │         ┌────── NO ┘    (+B 16番 / GND 4,5番 は切らずに直結)
                        │         │   切替リレー TQ2-5V（2回路で H/L を同時に切替）
                 ┌──────┴─────┐ ┌─┴──────────┐
                 │ CAN Pal #1 │ │ CAN Pal #2 │
                 │ 車両側     │ │ R-VIT側    │
                 │ 終端 OFF   │ │ 終端 ON    │
                 └──┬──────┬──┘ └──┬──────┬──┘
                  TX│    RX│     TX│    RX│
                 ┌──┴──────┴───────┴──────┴──┐
                 │ pin22 pin23   pin31 pin30  │
                 │  CAN1 (車両)  CAN3 (R-VIT) │
                 │         Teensy 4.1         │── pin2 ──> リレー駆動（2SC1815）
                 └─────────────┬──────────────┘
                               │ USB（電源＋シリアルコンソール）
                          PC / シガーUSB電源
```

| リレー | いつ | R-VIT のつながり先 |
| :--- | :--- | :--- |
| **OFF**（NC 側） | 無通電・起動中・ハング（WDT リセット中）・`x` コマンドで OFF | 車両に直結（物理スルー。Teensy 無しと同じ） |
| **ON**（NO 側） | `setup()` 完了後 | CAN Pal #2 ⇔ Teensy ⇔ CAN Pal #1 ⇔ 車両 |

- CAN Pal #1 は常に車両バスにぶら下がっているが、無電源の TJA1051 はバスから切り離されるので影響しない（終端は必ず OFF）。
- リレー OFF のとき CAN Pal #2 は R-VIT から切り離されるので、#2 の終端 120Ω が車両バスに入ることはない。

### 2.1 Teensy 4.1 使用ピン一覧

| Teensy ピン | 信号 | 接続先 | 備考 |
| :--- | :--- | :--- | :--- |
| **22** | CTX1 (CAN1 TX) | CAN Pal #1 **TX** | 車両側 |
| **23** | CRX1 (CAN1 RX) | CAN Pal #1 **RX** | 車両側 |
| **31** | CTX3 (CAN3 TX) | CAN Pal #2 **TX** | R-VIT 側 |
| **30** | CRX3 (CAN3 RX) | CAN Pal #2 **RX** | R-VIT 側 |
| **3.3V** | 電源出力 | CAN Pal #1 / #2 **VCC** | **5V にしないこと**（下記注意） |
| **GND** | GND | CAN Pal #1 / #2 **GND** | |
| **2** | GPIO 出力 | 1kΩ → 2SC1815 ベース | 切替リレー駆動。HIGH = Teensy 経由（2.5 節） |

### 2.3 CAN Pal（Adafruit 5708）の接続

| CAN Pal ピン | CAN Pal #1（車両側） | CAN Pal #2（R-VIT側） |
| :--- | :--- | :--- |
| VCC | Teensy 3.3V | Teensy 3.3V |
| GND | Teensy GND | Teensy GND |
| TX | Teensy pin **22** | Teensy pin **31** |
| RX | Teensy pin **23** | Teensy pin **30** |
| SLNT | 未接続（IC内部プルダウンで通常モード）。気になる場合は GND | 同左 |

| L | 車両側 OBD **14番** (CAN-L)（リレー NC と共通） | リレー **NO (7番)** |

### 2.4 OBD 延長ケーブルの加工

| OBD ピン | 信号 | 加工 |
| :--- | :--- | :--- |
| 6 | CAN-H | **切断**。車両側 → CAN Pal #1 H とリレー NC(2番)、R-VIT側 → リレー COM(3番) |
| 14 | CAN-L | **切断**。車両側 → CAN Pal #1 L とリレー NC(9番)、R-VIT側 → リレー COM(8番) |
| 4 | シャーシGND | 切らない（R-VIT 電源） |
| 5 | 信号GND | 切らない。ここから1本分岐して CAN Pal #1 の GND 端子へ（推奨） |
| 16 | +B | 切らない（R-VIT 電源） |
| 7 | K-LINE | 切らない（CKV36 は CAN のみ使用） |

- 線の色はケーブルごとに違うので、テスターで導通を確認してから切る。
- CAN H/L は撚ったまま、なるべく短く。

### 2.5 切替リレー（TQ2-5V）

Teensy の GPIO（pin 2）で 2SC1815 を ON/OFF し、リレーコイルを USB 5V（VIN）から駆動する。

```
 Teensy VIN (+5V) -----+-----------+
                       |           |  TQ2 pin1 (+)
                      [D1]        [RY]
                       |           |  TQ2 pin10 (-)
                       +-----------+
                                   |
                                 +-C-+
 Teensy pin2 ---[R1]---+---------B Q1|
                       |         +-E-+
                      [R2]         |
                       |           |
 Teensy GND -----------+-----------+
```

| 記号 | 部品 | 向き・接続 | 役割 |
| :---: | :--- | :--- | :--- |
| RY | TQ2-5V のコイル（秋月 117427） | 1番(+) を VIN 側、10番(−) を Q1 の C 側 | コイル 178Ω / 28.1mA、感動電圧 3.75V 以下 |
| D1 | 1N4148 | RY と並列。**帯（カソード）を VIN 側** | コイル逆起電力の吸収 |
| Q1 | 2SC1815 GR（hFE 200〜400） | C = RY の 10番、B = R1、E = GND | ベース電流 ≈ (3.3−0.7)/1kΩ = 2.6mA で 28mA を十分飽和 |
| R1 | 1kΩ | Teensy pin 2 ↔ Q1 の B | ベース電流制限 |
| R2 | 10kΩ | Q1 の B ↔ GND | 起動中・リセット中（ピンが入力）に確実に OFF |

- 2SC1815 の足は、印字面を手前・足を下にして左から **E C B**。
- GPIO 直結では駆動できない（3.3V は感動電圧 3.75V 未満、電流も超過）。

**TQ2-5V 端子配置**（データシート [tq.pdf](tq.pdf) の内部結線図より）

```
  BOTTOM VIEW（足側から見る）         TOP VIEW（印字面から見る＝ブレッドボードに挿した状態）
  方向指示マーク側                     方向指示マーク側
  ▼                                    ▼
    1   2   3   4   5                   10   9   8   7   6
   10   9   8   7   6                    1   2   3   4   5
```

- データシートの図は **BOTTOM VIEW**。ブレッドボード上では TOP VIEW（上下が入れ替わる）で読むこと。

| 端子 | 機能 | 接続先 |
| :--- | :--- | :--- |
| 1 / 10 | コイル **+** / **−**（極性あり） | VIN（1N4148 K） / 2SC1815 C（1N4148 A） |
| 3 / 8 | COM | R-VIT 側 CAN-H / CAN-L |
| 2 / 9 | NC（無通電で COM と導通） | 車両側 CAN-H / CAN-L |
| 4 / 7 | NO（通電で COM と導通） | CAN Pal #2 H / L |
| 5 / 6 | 未使用 | |

- 取り付け前にテスターで確認: 無通電で 3-2、8-9 が導通、3-4、8-7 が非導通。コイル 1-10 間 ≈ 178Ω。
- 1番に +5V、10番に GND を当てると 3-4、8-7 が導通に切り替わる（動作音は小さい）。逆極性では動作しない（実機で確認済み）。
  - 直列抵抗は不要（5V 定格コイルなので 5V 直結で 28mA）。電源は USB 5V / Teensy VIN 等の 5V を使い、12V は不可（最大印加 7.5V）。
  - Teensy 等の回路につながった 5V から試す場合は、離したときの逆起電力対策にコイルと並列に 1N4148（帯を 1番側）を入れておく。

**安全側に倒れる仕組み**

- ファームは CAN の初期化が終わった後（`setup()` の最後）に pin 2 を HIGH にする。それまでは R-VIT は車両直結。
- ウォッチドッグ（WDOG1、2 秒）を使用。`loop()` が 2 秒止まると Teensy がリセットされ、pin 2 が入力に戻ってリレー OFF → 車両直結。再起動後に自動で Teensy 経由に戻る。
- ウォッチドッグでリセットされた場合は、次の起動時のバナーに `!! 前回はウォッチドッグでリセットされた` と表示される。
- 切替の瞬間（動作・復帰 3ms 以下＋バウンス）は R-VIT 側でエラーフレームが出ることがあるが、CAN の再送で復帰する。

## 3. 電源・終端の注意

- **CAN Pal の VCC は必ず Teensy の 3.3V に接続する。** CAN Pal は VCC がそのままロジックレベル（VIO）になるため、5V を入れると RX が 5V 出力になり、5V トレラントではない Teensy 4.1 を壊す。CAN バス側の 5V はボード上のチャージポンプが生成する。
- Teensy 4.1 の 3.3V 出力は外部に 250mA 程度まで。CAN Pal 2個なら範囲内だが、他の 3.3V 負荷は増やさない（リレーコイルは VIN = USB 5V から取る）。
- **終端抵抗**
  - 車両側（#1）: 車両バスはすでに両端で終端済み。ON にすると約40Ωになり通信不良の原因になる → **OFF**。#1 はリレーに関係なく常に車両バスにつながっているので特に注意。
  - R-VIT 側（#2）: リレー ON 時は Teensy と R-VIT だけの独立バスになるので終端が必要 → **ON**。エラーが出る場合は R-VIT 側端にも 120Ω を追加（H-L 間が 60Ω になる）。リレー OFF 時は #2 ごと切り離されるので車両バスには入らない。
  - 確認: イグニッション OFF で車両側 OBD 6-14 番間 ≒ 60Ω、CAN Pal #2 の H-L 間 ≒ 120Ω。
- **GND**: CAN は差動だがトランシーバの同相電圧範囲（-12〜+12V）を外れないよう、Teensy 側と車両の GND 電位をそろえる必要がある。OBD 5番（信号GND）を CAN Pal #1 の GND 端子へつなぐのが理想だが、ブレッドボード段階では以下の給電方法で代用する。
  - **パターンA: シガーUSB電源 → ノートPC（USB-PD 給電）→ USB → Teensy**
    - シガーUSB電源は非絶縁の降圧なので、USB の GND = 車体 GND。ノートPC 経由でも Teensy の GND は車両と共通になる。
    - シリアルコンソールが使えるので、デバッグはこちら。
  - **パターンB: シガーUSB電源 → Teensy（PC なし）**
    - GND は同じく車両と共通。起動時の USB シリアル待ちは最大3秒で、PC なしでも PROXY モードで動き出す。
    - 状態はオンボード LED（R-VIT 受信で点滅）でしか分からない。
  - 共通の注意
    - 念のため、テスターでシガーUSB電源の USB シェル（GND）と車体間の導通を確認しておく（まれに絶縁型がある）。
    - ノートPC を家庭用 AC アダプタで動かしたまま車両の CAN につながない（PC の GND が交流電位を持つため）。
    - エンジン始動時の電圧降下でシガーUSB電源が落ちると Teensy が再起動する（その間はリレー OFF で R-VIT は車両直結）。
    - 症状が出たら（`txFail` が増える、`CAR rx` が止まる、R-VIT が通信エラー）まず GND を疑う。応急策として車体のボルト等から GND を取ってもよい。
- Teensy の電源が落ちると TJA1051 はバスから切り離され、リレーも OFF になるので、R-VIT は車両直結でそのまま動く（車両側にも影響しない）。

## 4. ファームウェアの動作

### 4.1 モード

| モード | 動作 | 用途 |
| :--- | :--- | :--- |
| **PROXY**（起動時） | R-VIT のリクエストを車両に流さず、Teensy がキャッシュ値で代理応答。未知のリクエストのみ車両へ素通し | 本命 |
| **BRIDGE** | 車両 ⇔ R-VIT の全フレームを双方向に素通し（直結と同等） | 配線確認、切り分け |

### 4.2 代理応答する DID（R-VIT → `7E0: 03 22 XX XX`、応答 → `7E8: 0n 62 XX XX ...`）

| DID | 内容 | 応答長 | 値の取得元 | 頻度 | 初期値 |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `11 01` | 水温 | 1 | 0x551 B0 + 10（= 水温+50） | ブロードキャスト | `88` |
| `11 02` | 車速 | 1 | 0x284 B4-5 ÷100 ÷2（km/h÷2） | ブロードキャスト | `00` |
| `11 1E` | スロットル | 1 | 0x160 B2-3 の上位9bit（255でクランプ） | ブロードキャスト | `00` |
| `12 01` | エンジン回転数 | 2 | 0x1F9 B2-3 ÷100（rpm÷12.5） | ブロードキャスト | `00 00` |
| `11 06` | 吸気温度 | 1 | Teensy が ECM に `22 11 06` | 10秒毎 | `5C` |
| `11 0A` | 点火時期 | 1 | Teensy が ECM に `22 11 0A` | 30ms毎（R-VIT 現行相当） | `58` |
| `11 1F` | エンジン油温 | 1 | Teensy が ECM に `22 11 1F` | 10秒毎 | `85` |
| `12 25` | A/F B1S1 | 2 | Teensy が ECM に `22 12 25` | 30ms毎（R-VIT 現行相当） | `01 3A` |

- 初期値は実データを受け取る前（車両未接続時など）に返す値。ログで観測したアイドリング付近の値。
- ポーリングは **R-VIT が直近 2 秒以内に要求してきた DID のみ** 行う。R-VIT 側で表示をやめた項目（例: 点火時期・A/F）は ECM に問い合わせない（`s` の src 欄が `idle` になる）。
  - 運用方針: 30ms 毎のポーリングが必要な点火時期・A/F は R-VIT で非表示にし、OBDLINK 併用時の ECM 競合を避ける（定義はソースに残す）。
- ポーリングで一度も取得できていない DID は 1 秒毎に再試行。タイムアウト 50ms、否定応答は表示して次へ。
- 変換・頻度は [src/main.cpp](src/main.cpp) 先頭の定数と `g_dids[]` で変更する。

### 4.3 未知のリクエスト（パススルー）

- 上表以外のフレームを R-VIT が送ってきた場合（起動時の車両確認やフロー制御フレーム等）は車両へ素通しし、その後 300ms 間は 0x7E8〜0x7EF の応答を R-VIT へ返す。
- 素通し中は Teensy 自身のポーリングを止め、ECU とのやり取りが混ざらないようにする。
- 未知フレームはシリアルに `UNK>CAR` として表示される（最大10件/秒）。ここに出たものは今後 `g_dids[]` に追加する候補。
- `u` コマンドで素通しを止めると、未知フレームは破棄（`UNK DROP`）。

## 5. シリアルコンソール

PlatformIO の Serial Monitor（115200bps、USB なので速度は実質無関係）で 1 文字コマンドを送る。

| キー | 機能 |
| :---: | :--- |
| `h` / `?` | ヘルプ |
| `s` | ステータス（カウンタ、DID ごとの現在値・更新からの経過ms・代理応答回数） |
| `a` | ステータス自動表示（1秒毎）ON/OFF |
| `p` | PROXY モード |
| `b` | BRIDGE モード |
| `q` | Teensy → ECM ポーリング ON/OFF |
| `u` | 未知リクエストの素通し ON/OFF |
| `f` | PROXY モードで車両ブロードキャストを R-VIT へ転送 ON/OFF（既定 OFF） |
| `v` | 詳細ログ（R-VIT 受信、代理応答、ポーリング）ON/OFF |
| `x` | 切替リレー ON/OFF（OFF = R-VIT を車両に直結。再起動すると ON に戻る） |
| `r` | カウンタリセット |

## 6. 立ち上げ手順（ブレッドボード）

1. **単体**: USB だけ接続して書き込み。シリアルにバナーが出ることを確認。
2. **リレー**: 起動後にリレーが「カチッ」と鳴り、バナーに `relay(pin2)=ON` と出ること。`x` で OFF/ON を切り替え、テスターで COM-NC / COM-NO の導通が入れ替わることを確認。
3. **R-VIT のみ（車両なし）**: CAN Pal #2 に R-VIT をつなぎ（R-VIT は別途 12V 給電）、`v` で詳細ログ。`RVIT>` と `PROXY<` が出て、R-VIT に初期値（水温 86℃ 等）が表示されれば代理応答 OK。
4. **車両側のみ**: CAN Pal #1 を車両へ。`s` で `CAR rx` が増え、`Coolant` / `EngineRPM` 等の age が小さい値で更新され続けること、`poll ok` が増えることを確認。
5. **物理スルー確認**: USB を抜いた状態（リレー OFF）で R-VIT が普段どおり動くこと。
6. **BRIDGE で全体確認**: `b` で直結相当にし、R-VIT が普段どおり動くことを確認（配線・終端の確認）。
7. **PROXY で本番**: `p` に戻し、R-VIT の表示が実車値に追従することを確認。`UNK>CAR` が出ていればメモしておく。
